# zpr-viewer

**今すぐ試すなら** → [zpr-viewer.html をブラウザで開く](https://todashuta.github.io/zpr-viewer/zpr-viewer.html)
（インストール不要。ファイル読み込みはローカルだけで、データを他所には送らない）

`.zpr`（ZPrint / ZEdit Pro のプロジェクトファイル）を、**依存ゼロの単一 HTML** で開いて眺めるビューア。
`zpr-viewer.html` をブラウザで開き、ファイルをドラッグ&ドロップするだけで、データはローカルから離れない。

対象は ZPrint / ZEdit Pro 側の `.zpr` だけ。同じ拡張子を使う他ソフトの `.zpr`（中身は別物）は読めない。

別途作成した Blender 用の ZPR エクスポートアドオンが書き出すファイルを読むことを最優先にしている（`.zpr` は
公開仕様が無いに等しいので、実測できるアドオン側の読み書きを正としてフォーマットを逆算した）。

## 使い方

```
ブラウザで zpr-viewer.html を開く → .zpr をドラッグ&ドロップ（または「ファイルを選ぶ」）
```

| 操作 | 動き |
| --- | --- |
| ドラッグ | 回転 |
| 右ドラッグ / 2本指ドラッグ | パン |
| ホイール / ピンチ | ズーム |
| ダブルクリック、`R` | 視点リセット（少し引いた位置に戻る） |
| `1` 色 / `2` テクスチャ / `3` ワイヤーのみ / `4` フラット / `5` UV | 表示モード |
| `W` | ワイヤーの重ね表示（**既定オフ**。ボタン「ワイヤー」でも切り替え） |
| `G` | 方眼グリッド |
| `C` | 両面表示の切り替え（オフで裏面を削る） |
| サムネイルクリック | テクスチャを拡大表示（`Esc` で閉じる、←→で別枚へ） |
| `P` | PNG 保存 |
| `?` | キー一覧の表示（`?` または `Esc` で閉じる） |

読み込み後は右のパネルから、方眼・両面表示・背景色・チャンク一覧が見られる。
埋め込みテクスチャのサムネイルをクリックすると拡大表示が出る（見ただけでダウンロードしてしまわないよう、
保存は拡大表示の中の「JPEG を保存」ボタンにしてある）。

### 表示モードについて

- **ワイヤーはモードに閉じず、トグルで重ねる**。色/テクスチャ/フラット/UV の上に `W` で線を載せられる。
  **初期状態はオフ**。最初から線が載っていると面の色とテクスチャのどちらを見ているか
  判別しづらく、そもそも線を引いていない面の方が見本なので、足すのはユーザーの操作にしてある。
  面を塗らずに線だけ見たいときはモード「ワイヤーのみ」（線が主役なので既定で引ける）。
- **フラット**はライティングを通さず、ファイルに書かれていた色をそのまま出す（色空間も変えない）。
- **UV**は `u` を赤、`v` に緑として描く。テクスチャがずれている原因が「UV の展開」なのか「画像の貼り込み」なのかを
  切り分けるのに使える。UV の無い面は何も描かない。
- **ライティング**は `draw()` にある 3 方向（key / fill / rim）だけで、光源はビュー空間に固定している
  （回しても影が追随するので形の凹凸が見えやすい）。光源の色は無彩色で、
  `viewer.keyCol` / `viewer.fillCol` で変えられる。`viewer.keyCol = viewer.keyDir` とすると、
  向きのベクトルを色に流用していた紫がった旧表示に戻る。

## 読んでいるチャンク

先頭は `u16 マジック 0x03AA`、`u32 作成者名長`、作成者名、`u8 version`、`u8 テクスチャの扱い`、4 バイトの末尾。
以降 `u8 タグ + u32 チャンク長（この 5 バイトを含む）+ 本体` が並ぶ。未知のタグは読み飛ばす。

| タグ | 中身 | 1レコード |
| --- | --- | --- |
| `0x0A` | 頂点 | `f32 x,y,z` + `u8 r,g,b` + `i32 uv` = 19B |
| `0x15` | 三角形（v3） | `u32 v0,v1,v2` + `u8 rgb ×3角` + `i32 uv` = 25B |
| `0x1F` | 埋め込みテクスチャ | `u32 枚数` + (`u32 名前長`, 名前, `u32`, flags4, `u32 format`, `u32 JPEG長`, JPEG) |
| `0x28` | 頂点 UV | 読まない（下記参照） |
| `0x32` | 面 UV | `i32 テクスチャ番号` + `f32 u×3` + `f32 v×3` = 28B |

- 面 UV は **1 三角形につき 1 レコード**。同じ頂点が三角形ごとに違う UV を持つので、テクスチャ付きの面は頂点を作り直して貼る。
- 面の色は三角形の角ごとの RGB を優先する（頂点側の RGB が使われていないファイルが多い）。色が無い面は白。
- テクスチャ名は UTF-8 として壊れなければ UTF-8、壊れるなら `shift_jis`（ZPrint/Windows 由来の cp932 名のため）、
  それも無理ならバイトをそのまま並べる。
- JPEG は `imageOrientation: "flipY"` で読み直す。ZPR の UV は `v=0` が画像下側なので、ここを省くと黙って上下反転する。
- 方眼とワイヤーのインク色は背景の輝度を見て裏返る（暗い背景なら明るい線）。背景と同系だと消えて見える。
  ワイヤーモードでは面塗りだけ `POLYGON_OFFSET_FILL` で深度を奥にずらして、面と同じ深さの線が負けないようにする。
- ワイヤーの線は **ブレンドを通さず不透明で**、viewport を 1px ずらして 2 回引く。1px 線に MSAA と
  alpha ブレンドを合わせると、カバレッジ 1/4 掛けで実機から消えた（SwiftShader だけだと見えてしまう）。

## テスト

```bash
python3 tests/test_zpr_viewer.py
```

Chrome をヘッドレス（SwiftShader）で起動し、実描画まで数値で確認する。スクリーンショットは使わず、
`gl.readPixels()` の被面積・平均色・`gl.getError()`・モデル規模などで判定する。

サンプル `.zpr` は Blender で作る（`tests/samples/` に無い場合は自動で skip される）:

```bash
# macOS 既定の場所以外の Blender を使いたい時は BLENDER でパスを渡す
BLENDER=${BLENDER:-/Applications/Blender.app/Contents/MacOS/Blender}
ZPR_ADDON=/path/to/io_export_zpr.py \
    "$BLENDER" -b --factory-startup --python tests/make_samples.py
```

ZPR を書き出す Blender アドオンはこのリポジトリには含めない。`ZPR_ADDON` で場所を教えるか、
ビューアと同じ場所・直下に `io_export_zpr.py` を置いておく（アドオンが無ければサンプルは作れないが、
既にあるサンプルでの検証はそのまま走られる）。

検証コードは本体には入れない。`tests/build_test_page.py` が `zpr-viewer.html` + `tests/inject.js` から
`zpr-viewer.test.html`（生成物・コミット不要）を作って、それに検証させる。ブラウザも同じ流儀で、
`CHROME=/path/to/Chrome` で実行ファイルを差し替えられる。

Chromium でも同じように回せる（snap 版 Chromium 156 で全件 PASS を確認）。
ただし systemd が動いていない環境（コンテナ内など。`/proc/1/comm` が `systemd` でない場合）では、
起動時の transient scope 作成に失敗し、その道連れで crashpad と FD ownership チェックが落ちる。
`DBUS_SESSION_BUS_ADDRESS=disabled:` を渡すと DBus を触らずに起動して通る。
プロファイルと一時ファイルの書き込み先も要るので、`HOME` / `TMPDIR` を書き込み可能な場所に向けておく:

```bash
P="$PWD"; mkdir -p .home .tmp/run
DBUS_SESSION_BUS_ADDRESS=disabled: \
  HOME="$P/.home" XDG_CONFIG_HOME="$P/.home/.config" XDG_CACHE_HOME="$P/.home/.cache" \
  XDG_RUNTIME_DIR="$P/.tmp/run" TMPDIR="$P/.tmp" \
  CHROME=/snap/chromium/current/usr/lib/chromium-browser/chrome \
  python3 tests/test_zpr_viewer.py
```

`.home/` と `.tmp/` は実行後に消してよい。`--single-process` なら FD ownership 違反は避けられるが、
WebGL は動くものの `file://` の fetch で落ちるので使わない。

カバーしている範囲: 頂点/三角形/色の規模、白塗り、JPEG デコード、テクスチャの貼り向き（4 隅の色と UV 値の両方）、
画像共有時のデコード重複、面 UV の無い面の描画残し、ワイヤーの遅延構築と**実際に線が描かれていること**、
色モードとテクスチャモードへのワイヤーの重なり、ワイヤーが**初期状態でオフ**なこと（トグルの
ボタン表示と実状態の一致も見る）、
パンの向き（ビュー行列から独立に求めたカメラ軸と比較）、リセット距離、フラット表示、方眼、
cp932 / UTF-8 / 不明なバイト列のテクスチャ名、ZPR でないファイル、途中で切れたファイル、18 万面。

## 読んでいないもの / 未確認

- `0x3E`（変換っぽいタグ）は意味を取りきれていないので**適用しない**。位置がズレて見えるファイルが出たらここが怪しい。
- `0x14`（v1 用らしい三角形）は読んでいない。Blender 側の出力も `0x15` のみ。
- `0x28`（頂点 UV）は使わない。ZEdit 側でも参照がずれるという話があり、面 UV (`0x32`) の方が実データと合う。
- テクスチャを外部ファイル名で参照する形式（ヘッダの扱いが `1`）は未対応。埋め込み (`2`) のみ。
- サブディビジョンレベルやグループ情報など、メッシュ以外の情報は復元しない（頂点・三角形・色・UV・JPEG だけ）。
- 実 ZPrint / ZEdit で保存したファイルでの検証は行えていない。自前の Blender エクスポートアドオンの出力と、
  ZPrint 7.5 保存の Ming vase を参考にした構造の推定に頼っている部分が残る。
